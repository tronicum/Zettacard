This is the exact same bug class already fixed twice elsewhere in this file (`.image-note`/`.image-illustration`, `.exam-modal`/`.exam-view` - both have an explicit `[hidden]` override) - it just was never applied to `.role-filters` when that feature shipped. Fixed with the same explicit override pattern: `.role-filters[hidden] { display: none; }` (specificity (0,2,0), strictly beats `.filters`'s (0,1,0), so this fix holds regardless of cascade/source-order questions). Audited every other `hidden`-attribute element in `app.html` against its own CSS class for the same bug class - only `.role-filters` had it; `.review-actions`, `.explanation`, `.module-switch-btn`, `.offline-prep-status`, `.exam-timer`, `.exam-skip-banner`, `.back-btn` etc. don't set `display` on their own bare class rule, so `[hidden]`'s native behavior already worked correctly for all of them.
